# Meeting Assistant presentation standards

The project is intended for a public audience through conference talks, technical blogs, and technology publications. Treat its interface and documentation as professional public-facing product materials.

## Language

- Write application interface text in English: navigation, labels, buttons, statuses, validation messages, and user-visible errors.
- Maintain one English-language `README.md`. Do not add translated README files or language-switch links.
- Preserve meeting names, transcripts, and other user-provided content in their original language. Audio language selection remains available.
- Conversation with the project owner may remain in Russian.

## Presentation

- Use clear, precise English, consistent terminology, and concise product copy.
- Keep typography, spacing, visual hierarchy, interactive states, and responsive layouts polished and consistent with the existing design.
- Make the README useful to first-time visitors: explain purpose, implemented capabilities, quick start, architecture, and material limitations.
- Keep examples, screenshots, commands, links, and architecture diagrams consistent with actual behavior.
- Distinguish implemented features from planned work. Describe external processing and local storage accurately. Support reliability and security claims with evidence.
- Explain concrete user benefits and engineering decisions without marketing exaggeration or unsupported claims of production readiness.

Review changes for English product text, visual consistency, documentation accuracy, and suitability for public demonstrations.
