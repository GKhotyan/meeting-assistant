# Engineering Assistant — согласованный объём и проект решения

Дата: 2026-10-26. Статус: объём согласован в разговоре; технические решения ниже — предложение исполнителя, до живого эксперимента.

## Цель

Самостоятельный проект в `/Users/georgy/Documents/engineering-assistant`, который запускается в Docker на Mac, затем на Linux VPS. Бот входит в Zoom по ссылке под заданным именем, записывает аудио встречи и отдельно видео всего виртуального экрана бота. Сервисы, аккаунт и API Vexa для работы не нужны.

## Первая версия

- Браузер: имя бота (исходно Engineering Assistant), ссылка Zoom, «Подключиться», «Остановить», статус и ошибки, готовые файлы для скачивания.
- Предлагаемый предел: одна активная встреча; повторный запуск получает понятный отказ, не второй браузер на том же дисплее.
- Аудио отдельным файлом на встречу. Исходная запись — WebM/Opus, итоговый контейнер нормализован, есть длительность и перемотка.
- Видео содержит весь виртуальный экран бота с развёрнутым Zoom: демонстрацию, камеры и интерфейс, если они отображаются. Это не захват рабочего стола Mac пользователя.
- Видео без звуковой дорожки, аудио отдельно. Запись обоих файлов идёт всю встречу, в том числе без демонстрации.
- Итог: `audio.webm`, `screen.mp4`, `session.json` с временными смещениями для сопоставления записей. Последующее выделение демонстрации вне первой версии.
- Рабочий каталог данных подключается с хоста: `./data:/data`. На Mac файлы видны в `engineering-assistant/data/recordings/<session-id>/`; на VPS тот же каталог находится на диске сервера, из браузера доступны скачивания.
- Имя бота и метаданные переживают перезапуск. Артефакты не удаляются при пересоздании контейнера.
- Закрытие страницы браузера пользователя не останавливает бота. Mac/VPS и Docker должны продолжать работать.
- Deepgram, транскрипция, календарь, другие платформы, несколько пользователей и параллельные встречи — вне первой версии.

## Подходы

1. Перенести Vexa Lite и отключить лишнее: быстрее начать, но остаются БД, runtime и object storage, что противоречит цели небольшого самостоятельного проекта.
2. Выделить Zoom-подключение и запись, написать маленькую локальную оболочку: рекомендуемый подход; повторно используем проверенные части, заменяем HTTP/S3-выгрузку записью на диск.
3. Написать Zoom-бота заново: теряем уже работающие допуск, выход и определение удаления; преимуществ для этой задачи не выявлено.

## Предлагаемая архитектура

Один Compose-сервис: Node.js + TypeScript, HTTP API со статической страницей, управляемый worker-процесс с Chromium/Playwright и Xvfb, FFmpeg для завершения файлов. UI не управляет браузером напрямую. Worker сообщает статусы серверу через IPC; контроллер ставит взаимное исключение на запуск встречи и пересылает команду остановки. Docker socket приложению не нужен. Отдельные Redis, PostgreSQL и S3 не нужны.

Внешний интерфейс: `POST /api/sessions` с `{meetingUrl, botName}`, `POST /api/sessions/:id/stop`, `GET /api/sessions`, `GET /api/sessions/:id`, `GET /api/sessions/:id/files/:fileId`, `GET/PUT /api/settings`. Идентификаторы файлов разрешаются через manifest, произвольные пути не принимаются.

Статусы: queued, joining, waiting, recording, stopping, completed, failed, interrupted. Незавершённые сессии после перезапуска отмечаются interrupted, доступные файлы сохраняются. Повторно входить в встречу автоматически после аварии без отдельного решения не будем.

Mac по умолчанию слушает `127.0.0.1`. Для VPS требуется включённая аутентификация и HTTPS на reverse proxy; не публиковать интерфейс без защиты. Пароли и Zoom passcode в журналах не показывать. Обычные Zoom HTTPS invite links; корпоративные порталы/SSO и запрет гостевых ботов — понятная ошибка, не обещание обхода ограничений.

## Технический эксперимент и изменение объёма

Пользователь 2026-10-26 явно разрешил запись всего экрана вместо screen-share-only, чтобы упростить первую версию. Во время тестовой Zoom-встречи бот Engineering Assistant допущен, демонстрация видна. FFmpeg x11grab дал 10-секундный H.264 MP4, 1920×1080, без аудиодорожки. Первый кадр проверен: Zoom и демонстрация присутствуют, но окно не развёрнуто и есть popup. Не считать это готовой продуктовой записью: полноэкранный режим и закрытие popup проверяются отдельно. Исследование точного источника демонстрации больше не является блокирующим.

## Проверка результата

- Чистая сборка из нового проекта без доступа к соседнему `vexa` и его Docker images.
- Реальный Zoom: заданное имя, допуск из waiting room, слышимая тестовая фраза в аудиофайле.
- Две демонстрации с остановкой между ними, изменением размеров и камерами участников; итоговое видео отражает всё окно Zoom и не имеет звуковой дорожки.
- Без демонстрации: аудио и видео продолжают записываться.
- Stop из интерфейса, завершение хостом, `docker compose stop`: финальный хвост записи сохранён, worker завершился.
- Аварийное завершение: сохранённые части не удалены, сессия interrupted, неопубликованные файлы явно помечены неполными.
- `ffprobe` и полное декодирование итоговых файлов без ошибок; проверка содержимого вручную. Unit green не заменяет живой прогон.
- Пересоздание контейнера сохраняет настройки и записи; скачивание соответствует файлу на диске.
- Linux VPS проверяется отдельно; Mac Docker не считается свидетельством VPS.
