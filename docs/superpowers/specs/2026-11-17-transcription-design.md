# Meeting transcription

Approved UX: clicking a meeting title or free card area opens its own view with Recording and Transcription tabs. Keep downloads/delete actions independent. Card transcript status links directly to Transcription. Deep links and browser Back work. Russian default, diarization off. Summary remains a later step.

Manual server-side Deepgram Nova-3 upload of a completed meeting's finalized audio only. File selector handles multiple audio files; use the saved encrypted credential. Language choices match analyzer (ru/en/de/fr/es/it/pt/uk/multi). Smart formatting, utterances, optional diarize_model=latest. Never upload on navigation. Explain external transfer on submission. One processing job at a time; reject duplicate/concurrent submissions with 409 instead of retrying paid work.

Store transcription state and normalized result atomically in the meeting directory, outside session.json. API GET/POST /api/sessions/:id/transcription; list adds compact transcription status. Processing continues after navigation. On server restart unfinished work is marked interrupted and never retried automatically; communicate possible paid completion before retry. Previous successful result remains visible on failure/retry. Block meeting deletion during a job. Inputs are manifest-ready audio, safe basename, no symlink, regular nonempty file up to 2GB; stream from disk, 660s timeout, provider response at most 64MiB. Sanitize external errors, never log provider bodies/credentials.

Meeting view: back link, title/date/status, two accessible keyboard tabs, audio player shared with transcript timestamps, recording downloads, language/audio/diarization controls, status/error/retry and timestamped segments/speaker labels. Show plain text fallback if no utterances or no speech. Preserve player position, options and user focus during polling. Ignore late responses after navigating elsewhere. Finished transcripts survive reload/restart. Playback supports byte ranges for seeking. Build DOM using textContent for untrusted transcript/title.

Implementation choice: hash routes in existing vanilla JS shell, a dedicated meeting.js controller; dedicated TypeScript transcription service using Node fetch/crypto/fs, no new dependencies. Testing uses synthetic recordings and provider transport fixtures; no real recording upload. Existing Settings changes remain in checkout.
